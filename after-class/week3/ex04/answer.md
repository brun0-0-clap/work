# ex04 高Star开源项目README对比分析

选取3个1000+ Star 的GitHub开源项目：
1. nvm（Node版本管理工具）
2. requests（Python HTTP库）
3. ripgrep（命令行文本搜索工具）

## 一、各README中有用的内容
1. **快速安装步骤**：给出一行式安装命令，用户可以直接复制运行，快速上手。
2. **最小使用示例**：简短的代码/命令示例，看完就能知道这个工具能干什么。
3. **依赖与系统要求**：写明支持的操作系统、需要的软件版本。
4. **常见问题FAQ**：收集新手容易踩坑的问题，减少重复issue。
5. **简单的贡献指南**：告诉开发者如何提交Issue、PR。

## 二、属于噪音、价值较低的内容
1. 大段项目历史故事、冗长的开发心路历程，和使用无关。
2. 大量无关宣传截图、装饰性大图，挤占阅读空间。
3. 过多的徽章堆砌，几十种状态徽章，喧宾夺主。
4. 过度冗长的开发内部细节，普通使用者完全不需要了解。

## 三、给自己写README的借鉴总结
1. 优先放：**安装方式 + 最小示例**，放在文档最开头，用户打开第一眼就能看到。
2. 补充：系统依赖、简单FAQ、基础贡献说明。
3. 少放：无关故事、大量装饰图片、过多徽章。
4. 区分普通使用者和开发者内容，把开发者相关内容放到靠后的章节，不要干扰普通用户阅读。
