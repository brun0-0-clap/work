# ex10 GitHub issue质量评估

模拟一个带有`good‑first‑issue`标签的issue：

### Issue描述
> 问题：命令行工具输出的提示文字存在一处拼写错误。
> 复现步骤：运行xxx命令，查看终端输出。
> 预期：单词拼写正确。
> 实际：单词拼写错误。
> 环境：Ubuntu 22.04，Python3.10。

### 评估
1. 是否清晰描述现象：是，明确写出了现象。
2. 是否提供复现步骤、版本信息：全部提供。
3. 维护者是否还需要追问提交者：几乎不需要，信息完整。
4. 总体质量：这是一份质量很高的good‑first‑issue，新手可以根据描述直接定位修改位置。

## 总结：高质量issue应当包含
1. 运行环境、软件版本
2. 复现问题的操作步骤
3. 实际发生了什么、你期望发生什么
4. 相关报错、日志输出
